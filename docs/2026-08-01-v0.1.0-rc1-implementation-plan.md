# Envizzle v0.1.0-rc1: staged build supervision + truthful graphics verification

## Context

Envizzle today is a deterministic *prompt generator*: `assemble.mjs` combines `TEMPLATE.md`'s 38 tokens with `references/*.md` content and `selection.mjs` choices into a brief + `ENVIZZLE_BUILD.json` (7 top-level keys, 3 frozen milestones). It's good at describing *what* to build but has no mechanism to stop a smaller coding model from redesigning the architecture, faking readiness, or building later systems on top of broken ones. This task converts it into a *build supervisor*: a canonical, strictly-validated assembly model that emits (a) a 5-stage implementation plan the builder must follow one stage at a time, (b) forbidden/approved pattern registries statically checked against the built project, (c) truthful runtime lifecycle/diagnostics hooks (`window.__demo`) that can't fake readiness, and (d) a verifier that enforces all of it. Prompt and contract must be generated from one canonical model so they can never disagree.

**Product principle** (render prominently in prompt + contract, sourced from `sourceOfTruth`): "The builder implements an already-designed system. It may make bounded implementation decisions inside each approved stage, but it may not redesign the renderer, terrain ownership, shader integration, fallback strategy, module responsibilities, readiness lifecycle, verification interfaces, or stage order." Plus: builder works one stage at a time; must not continue after a failed checkpoint.

**`implementationPlan[]`** — exactly 5 entries, this ID/order, each field per this schema:
```json
{
  "id": "backend-proof", "order": 1,
  "goal": "...", "allowedScope": [], "requiredOutputs": [],
  "approvedPatternIds": [], "forbiddenPatternIds": [],
  "automatedChecks": [], "visualChecks": [], "stopConditions": [],
  "requiredEvidence": [], "doNotProceedUntilPassed": true
}
```
Stage IDs/order/content:
1. `backend-proof` — allowedScope: engine initialization; one representative material; one representative mesh; required backend diagnostics; GPU validation capture; one successfully completed frame; truthful readiness state. Forbidden this stage: full terrain, character, particles, mechanic, atmosphere, fallback renderer. requiredOutputs/proof: selected backend active; selected shader language active; representative shader processed by selected engine; pipeline and bindings valid; representative material compiles; material becomes ready; validation error list empty; ≥1 submitted frame completes; readiness changes to true only after all prior proof succeeds.
2. `terrain-kernel` — allowedScope: one terrain patch; GPU-owned visual elevation; flat CPU-built render vertices; CPU mirror used only for physics/camera-clearance/foot-planting; GPU parity evaluation; normals; camera clearance. Stop condition: do not add clipmap rings until the single patch passes.
3. `environment-composition` — allowedScope: continuous terrain expansion; clipmap or nested-ring LOD; biome morphology; far field; lighting; atmosphere; initial camera composition. requiredEvidence includes: idle screenshot must already clearly resemble the selected biome before character development begins.
4. `character-locomotion` — allowedScope: procedural character; intentional silhouette; idle animation; locomotion; foot planting; appropriate camera framing; character visibility verification. stopConditions: character must not be a placeholder primitive; idle and locomotion must be visually distinguishable.
5. `mechanic-polish` — allowedScope: centrepiece mechanic; particles and secondary effects; final materials; final lighting; performance cleanup; complete evidence; final visual review. requiredEvidence: mechanic capture must be immediately distinguishable from both idle and locomotion.

**Terrain elevation ownership** (put inside `architecture{}` as `architecture.terrainElevationOwnership`):
```json
{
  "renderOwner": "gpu", "renderMeshBaseHeight": 0,
  "cpuHeightPurpose": ["physics","camera-clearance","foot-planting"],
  "forbidCpuPredisplacedRenderVertices": true,
  "requireCpuGpuParityTest": true, "parityToleranceM": 0.03
}
```
Prompt meaning text (render verbatim): "Render terrain vertices must enter the terrain vertex shader at base height y = 0. Apply procedural elevation exactly once, on the GPU. The CPU may mirror the same height function only for physics, camera clearance, and foot planting. CPU-built render vertices must not be pre-displaced."

**Architecture ownership map** (babylon-webgpu profile — mirror structure for three-webgl2 with equivalent files):
```
src/core/engine.js         — WebGPUEngine init, adapter/device failure, unsupported-backend behavior
src/core/gpuValidation.js  — validation scopes, uncaptured errors, device loss, validation-error storage

src/core/settings.js       — approved feature toggles only
src/shaders/               — Babylon-compatible WGSL sources + shared shader functions
src/terrain/heightfield.js — CPU height mirroring for physics, camera clearance, foot planting ONLY
src/terrain/parity.js      — GPU evaluation/readback + CPU/GPU parity comparison
src/terrain/               — GPU-rendered terrain mesh + LOD system
src/character/             — rig, silhouette, animation, visibility, foot placement
src/mechanic/               — centrepiece mechanic + mechanic verification state
```
Builder may split files further only when responsibilities stay unchanged and the deviation is documented.

**Minimum `forbiddenPatterns[]` IDs** (all profiles unless noted): `webgl-fallback`, `manual-babylon-bindings` (babylon-webgpu only), `wrong-babylon-shader-language` (babylon-webgpu only), `wrong-babylon-shader-store` (babylon-webgpu only), `duplicate-terrain-displacement`, `cpu-predisplaced-render-mesh`, `premature-readiness`, `suppressed-initialization-failure`, `placeholder-character`, `indistinguishable-poses`, `render-loop-allocation`, `incomplete-evidence`, `continue-after-failed-stage`. **Truthful `window.__demo` hook** (replaces the entire old hook, breaking change — update every reference simultaneously: `TEMPLATE.md` §6, `verify/README.md`, `verify_demo.mjs`, `gates.mjs`, `report.mjs`, `build-contract.mjs`'s `ACCEPTANCE_GATES.camera.hook` field):

**GPU validation blocking-concept matcher** (case-insensitive substring/keyword match against console/JS errors): treat as blocking — `GPUValidationError`, "uncaptured" + "error", "duplicate binding", "bind group", "pipeline creation", "shader compilation", "material compilation", "adapter unavailable", "backend fallback", "WebGPU initialization failure", "device lost", "missing vertex buffer", "incompatible vertex input", "incompatible varying" / "incompatible output structure", "invalid entry point".
